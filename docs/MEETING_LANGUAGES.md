# 會議語言預設

採用設計方案 1：在既有工作台設定中集中管理三個欄位，顯示 Agent 將讀取的設定預覽。按完成儲存；失敗保留輸入，版本衝突需重新載入，避免覆寫另一個視窗的設定。

流程：設定頁 → 同源設定 API → 本機 meeting-preferences.json → CLI/config → 新場次 status.json 語言快照 → 平台字幕設定與讀回 → 正確語系的本機備援 → 逐字稿原文／翻譯顯示。

預設：中文辨識、原文跟隨會議語言、英文翻譯。可選英、德、日、韓；跟隨會議語言會在建立場次時解析為具體語言。原文顯示「全部」保留全部段落；德日韓篩選保留未標註語言的舊段落，不自行猜測語言。

資料存放在實際資料目錄；Windows 安裝版通常為使用者 AppData/Local/DuckMeeting/data。外觀仍為瀏覽器設定，語言預設則跨 Agent 共用。既有場次不會被修改。CLI 明確字幕參數及環境設定可覆蓋共用預設；網頁明確 primary/secondary URL 參數覆蓋本場閱讀設定。

Google Meet 和 Teams 的字幕語言需可觀察讀回才算已驗證。Teams 權限限制或其他人的轉錄可能阻止變更；程式保留未驗證狀態，不停止轉錄。非中文備援只載入既有 Whisper 快取，缺模型時明確提示，不自動下載。中文仍走 Paraformer。

驗收邊界：自動化已覆蓋設定 API、並行儲存衝突、UI 持久化、原場次隔離、桌面／手機、明暗主題及平台設定讀回；真人平台政策、權限與各語言辨識準確度仍需實際會議驗收。本次沒有加入真實會議、沒有更改正式安裝版本。
