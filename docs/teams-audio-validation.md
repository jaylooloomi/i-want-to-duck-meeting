# Teams 本機雙路音訊驗證

日期：2026-10-24（Asia/Taipei）

## 真實 Teams 會議驗收狀態：尚未通過

2026-10-24 再次嘗試使用受支援的瀏覽器工具開啟 `https://teams.microsoft.com/`，此次工具可正常導向 Teams，再導向 Microsoft 登入頁。頁面顯示「登入」、電子郵件／電話／Skype 輸入欄及「下一步」，沒有可用的登入工作階段。尚未建立或加入 Teams 測試會議，也沒有完成兩個獨立與會端的即時語音測試。

因此下方既有雙路錄音測試不代表真實 Teams 會議驗收；遠端即時發言、本人實體麥克風的可理解發言，以及通話中 A／B 穩定性三項均仍未驗收通過。本次未使用播放錄音替代測試。

## 實作與驗證結果

Teams 模式同時擷取所選 Windows 播放裝置（WASAPI loopback）與所選輸入裝置，兩路各自做語音偵測、保留聲音來源，再以同一個本機 Whisper 模型辨識。
本機輸入固定為講者 A，遠端聲音以保守分群從 B 開始，不確定時顯示「講者未確認」。

完整測試使用兩段已知不同人的公開真人錄音，經兩個不同的 Windows 實際播放／擷取路徑，再透過網頁的 Teams 操作流程啟動與停止。
辨識 API、音訊回呼與講者結果沒有使用假資料替換；Windows 預設播放／麥克風設定未更動。

| 核對項目 | 結果 |
|---|---|
| 本機輸入錄音 | 51.477 秒；非零峰值 10508 |
| 會議播放錄音 | 51.477 秒；非零峰值 23839 |

| 刻意安排兩路同時說話 | 兩路都有文字，時間戳重疊超過 1 秒，仍分別為 A／B |
| 停止收尾 | 最後片段保存、兩路裝置關閉、暫存清空、狀態 done、error 為 null |
| 外部傳輸 | 頁面請求全部為 localhost，語音模型離線載入 |

測試裝置：本機輸入使用 NVIDIA HDMI 播放端的可控制 loopback，遠端使用既有 VB-Audio 播放端的 loopback；兩路播放端不同。
這能自動核對已知音訊，不要求使用者配合發言。正常產品使用可直接選實體麥克風，不需要安裝 VB-Audio。

另已開啟實體 USB Microphone 並保存非零 PCM 訊號（短裝置測試峰值 451；較長測試曾達 3463）。
實體麥克風沒有清楚收到自動從其他播放裝置播放的測試發言，因此該次檢查只證明裝置可開啟並擷取訊號，不列為本人語音內容核對通過。
此次沒有登入／加入真人 Teams 會議；驗證的是 Teams 所使用的 Windows 播放與輸入擷取流程，以及實際錄音、辨識、分群與網頁整合。

## 使用範圍

播放端是所選裝置上全部程式的聲音，不是 Teams 程序專屬擷取。應選擇與 Teams 相同的裝置，使用耳機避免遠端聲音回錄到本機麥克風。
遠端多人彼此重疊、房間回音、實體麥克風收音距離及逐字稿錯字仍可能影響結果；本機與遠端兩路彼此重疊則已測試。
原生收音在網頁背景仍持續；心跳容許瀏覽器每分鐘才執行一次計時器，異常離線超過 3 分鐘才自動收尾。
驗證方式與可重跑命令見 README 的 Teams 章節。

API 依據：[Microsoft WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)、[PyAudioWPatch](https://pypi.org/project/PyAudioWPatch/)。
