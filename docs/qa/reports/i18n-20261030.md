# Interface localization — 2026-10-30

## Delivered behavior

- Traditional Chinese (default), English, Japanese and Korean interface languages in the sidebar footer.
- Bundled UI catalog; no model or translation API is used for interface localization. Original-text filtering and transcript translation remain separate.
- Static localization binds only the authored initial UI nodes, not a MutationObserver over live content. Dynamic UI messages use explicit lookup calls. User-controlled titles are protected even when identical to a default UI label. Source Markdown, names and utterances are never translated by the interface switch.
- Preference persistence and cross-tab updates; blocked storage leaves the current page usable with a persistence warning.
- In-place changes preserve recording and playback. Full localized date strings are preserved (including Korean spaces). Both appearance themes remain available.
- Fixed notes card redraw ordering, longer bilingual preset labels and microphone placeholder labels during language changes.

## Tests and evidence

Focused command: `node --test --test-concurrency=1 test/qa/i18n.test.js`

Full command: `node --test --test-concurrency=1 "test/unit/**/*.test.js" "test/qa/*.test.js"`

Thirteen localization browser cases cover four locales at 1280/390 widths, both themes, dialogs, keyboard category navigation, persistence, independent translation controls, cross-tab storage, denied storage, exact original content/XSS-like text, real AudioWorklet PCM upload to an isolated HTTP service, and continued WAV playback with no navigation. Every browser case uses console/page-error guards. Original source Markdown is compared byte-for-byte after switching.

Synthetic screenshots: `docs/design/i18n-20261030/{zh-TW,en,ja,ko}/actual.png`. The fixture intentionally retains Chinese meeting titles/notes and bilingual utterances to demonstrate that interface localization does not rewrite content. These are demonstration data, not user meeting recordings.

The initial regression exposed a test locator that retained the old Chinese accessible name after switching. A focused rerun also exposed a test that required a completion message to remain visible after its recording panel intentionally hid. Selectors now follow localized accessible names; stop verification waits for the real stop response and completed meeting state. No sleeps or force clicks were added.

## Limits

This change does not add a speech model, change platform caption recognition, translate source notes automatically or prove live Japanese/Korean ASR quality. Raw OS device names, user notes and unknown backend/Agent diagnostic strings retain their source language. Existing BUG-004 resource-error cases remain skipped in the broad suite; no new skips were introduced.

No private meeting data was uploaded, added to these fixtures or submitted to Git. The standalone local viewer was restarted after confirming that there were no active meeting recordings. Localization assets returned HTTP 200 from the installed local viewer.

- Successful full unit/QA regression: **661 tests, 645 passed, 0 failed, 16 pre-existing skips** (380.165 seconds).
- Final localization and integrity replay after the Japanese compact-control width adjustment: **16 passed, 0 failed, 0 skipped** (43.872 seconds). Includes explicit rendered overflow checks on both category buttons.
